# Справочник модулей School Psychology Testing App

## 1. Назначение документа

Документ описывает текущее состояние проекта на дату подготовки справочника. Для каждого Python-файла указаны назначение, классы, функции и методы. Пустые или незавершенные файлы отмечены отдельно: наличие файла в дереве проекта не означает, что в нем уже есть рабочая логика.

Основная реализованная ветка приложения - desktop-приложение на PySide6 с PostgreSQL. В проекте также присутствуют заготовки REST API, Alembic-миграций и отдельных utility-модулей.

## 2. Общая архитектура

Система состоит из следующих слоев:

1. **Точка входа** - `main.py` создает Qt-приложение, настраивает логирование, подключает сервисы и показывает авторизацию.
2. **GUI** - окна PySide6. Главное окно выбирает рабочий кабинет по роли пользователя.
3. **Сервисы** - бизнес-логика авторизации, подключения к БД, расчета результатов и формирования отчетов.
4. **Модели** - dataclass-объекты предметной области: пользователь, ученик, школа, класс, тест и результат.
5. **Конфигурация** - `config/settings.py` читает параметры из `.env` и переменных окружения.
6. **PostgreSQL** - сервис БД работает со схемой `psychology`, пулом соединений и SQL-запросами.
7. **Тесты** - pytest-тесты конфигурации, моделей, сервисов и подключения к БД.

Главный сценарий:

```text
main.py
  -> DatabaseService
  -> AuthService
  -> AuthWindow
  -> authenticate_user()
  -> MainWindow
  -> AdminDashboard / StudentDashboard
  -> DatabaseService
  -> PostgreSQL
```

Роли, используемые приложением:

- `admin` - административная панель;
- `psychologist` - в текущем `MainWindow` направляется в `AdminDashboard`, хотя отдельный `PsychologistDashboard` тоже существует;
- `student` - личный кабинет ученика.

## 3. Запуск приложения

### `main.py`

Главная точка входа desktop-приложения.

- Создает каталог `logs` и файл `logs/app.log`.
- Настраивает два обработчика логов: файл и консоль.
- Добавляет корень проекта в `sys.path`.
- Внутри `main()` лениво импортирует тяжелые библиотеки и GUI-компоненты.
- Создает `QApplication`, устанавливает стиль `Fusion`, шрифт и палитру.
- Создает `DatabaseService` и `AuthService`.
- Открывает модальное `AuthWindow`.
- После успешного входа создает и показывает `MainWindow`.
- При исключении пишет ошибку в лог, выводит traceback и завершает процесс с кодом 1.

Функция:

- `main()` - полный сценарий запуска приложения, первичной настройки Qt, авторизации и передачи данных пользователя в главное окно.

## 4. Конфигурация

### `config/__init__.py`

Пакет конфигурации. Собственной логики нет.

### `config/settings.py`

Центральный объект настроек приложения.

#### Класс `Settings`

Наследуется от `pydantic_settings.BaseSettings`, поэтому значения могут задаваться через `.env` и переменные окружения.

Поля:

- `DB_HOST`, `DB_PORT` - адрес и порт PostgreSQL;
- `DB_NAME`, `DB_USER`, `DB_PASSWORD` - база, пользователь и пароль;
- `DB_SCHEMA` - схема PostgreSQL, по умолчанию `psychology`;
- `SECRET_KEY` - ключ подписи JWT;
- `ALGORITHM` - алгоритм JWT, по умолчанию `HS256`;
- `ACCESS_TOKEN_EXPIRE_MINUTES` - срок жизни токена;
- `ENCRYPTION_KEY` - ключ шифрования дополнительных данных;
- `APP_ENV`, `DEBUG`, `LOG_LEVEL` - режим и параметры приложения;
- `API_HOST`, `API_PORT` - настройки будущего API.

Методы и свойства:

- `database_url` - собирает URL PostgreSQL из параметров подключения.
- `project_root` - возвращает путь к корню проекта относительно каталога `config`.
- `model_config` - конфигурация Pydantic: файл `.env`, UTF-8, игнорирование лишних переменных.

Глобальный объект `settings` создается при импорте модуля и используется остальными компонентами.

## 5. Сервисы

### `src/services/__init__.py`

Реэкспортирует `AuthService` и `DatabaseService`, чтобы их можно было импортировать из пакета сервисов.

### `src/services/auth_service.py`

Сервис аутентификации, хеширования паролей, JWT и проверки пользователя в БД.

#### Класс `AuthService`

Конструктор:

- `__init__(db_service)` - принимает `DatabaseService` через dependency injection и сохраняет его в `self.db`.

Методы:

- `verify_password(plain_password, hashed_password)` - проверяет пароль через bcrypt. При ошибке пишет событие в лог и возвращает `False`.
- `get_password_hash(password)` - создает bcrypt-хеш. Пароль кодируется в UTF-8 и ограничивается первыми 72 байтами, что соответствует ограничению bcrypt.
- `create_access_token(data, expires_delta=None)` - копирует полезную нагрузку, добавляет `exp`, подписывает данные через JWT и возвращает строку токена.
- `decode_token(token)` - проверяет подпись и срок действия JWT. При `JWTError` возвращает `None`.
- `authenticate_user(login, password)` - ищет пользователя в `psychology.users`, проверяет пароль, `is_active`, после чего возвращает словарь с идентификаторами, логином, ролью, `student_id`, `school_id` и флагом верификации.

Особенность: `ACCESS_TOKEN_EXPIRE_MINUTES` объявлен в настройках, но текущий метод `create_access_token()` использует значение 60 минут по умолчанию напрямую.

### `src/services/database_service.py`

Главный слой доступа к PostgreSQL. Отвечает за соединения, классы, учеников, учетные записи, тесты, вопросы, прохождение тестов, результаты, отчеты, импорт PDF и уведомления.

#### Класс `DatabaseService`

Использует Singleton для обычного режима и отдельный экземпляр для тестов.

Константы:

- `DEFAULT_SCHOOL_ID` - идентификатор школы по умолчанию;
- `DEFAULT_YEAR_ID` - идентификатор учебного года по умолчанию;
- `_instance` - обычный экземпляр Singleton;
- `_connection_pool` - пул соединений;
- `_for_tests` - признак тестового экземпляра.

Системные методы:

- `__new__(for_tests=False)` - возвращает общий объект либо отдельный объект при `for_tests=True`.
- `__init__(for_tests=False)` - инициализирует пул только при его отсутствии, чтобы повторные вызовы не создавали новые соединения.
- `_initialize_pool()` - формирует параметры подключения, временно очищает Windows `PATH`, создает `ThreadedConnectionPool` с диапазоном 5-35 соединений и восстанавливает окружение.
- `get_connection()` - контекстный менеджер выдачи соединения из пула и его гарантированного возврата.
- `get_cursor()` - контекстный менеджер курсора; управляет соединением, транзакцией, commit/rollback и освобождением ресурсов.
- `close_all()` - закрывает все соединения пула и сбрасывает ссылку на пул.
- `reset_for_tests()` - classmethod для сброса состояния Singleton между тестами.

Работа с классами:

- `get_all_classes()` - возвращает список классов школы для административной таблицы.
- `add_class(title, parallel, letter)` - создает новый класс и возвращает его идентификатор.
- `update_class(cid, new_name)` - изменяет название класса.
- `delete_class(cid)` - удаляет или деактивирует класс по идентификатору.

Работа с учениками и доступом:

- `get_students_by_class(class_filter_uuid=None)` - получает учеников, при необходимости фильтруя по классу.
- `add_student(s_code, f_name, l_name, m_name, ..., consent_given=False)` - добавляет ученика, возвращает UUID; персональные поля подготавливаются для хранения в зашифрованном виде.
- `add_student_with_account(..., login, password_hash, consent_given=False)` - атомарно создает профиль ученика и связанную учётную запись; при сбое транзакция откатывается.
- `update_student(sid, f_n, l_n, m_n, ...)` - изменяет данные существующего ученика.
- `delete_student(stud_uuid)` - удаляет или деактивирует ученика.
- `create_student_account(student_uuid, login_str, hashed_pass)` - создает учетную запись и связывает ее со студентом.
- `revoke_student_access(student_uuid)` - отзывает доступ ученика к системе.
- `get_student_profile(user_uuid)` - получает профиль ученика по идентификатору пользователя.

Работа с тестами:

- `get_all_tests()` - получает список методик для администратора.
- `add_test(code, name, desc, instructions='')` - создает заголовок новой методики.
- `update_test_metadata(test_id, code, name, desc, instr)` - изменяет основные сведения и инструкции теста.
- `delete_test(test_id)` - удаляет или деактивирует тест.
- `get_test_full_structure(test_id)` - загружает вопросы, шкалы и структуру методики.
- `save_test_structure(test_id, questions, scales)` - сохраняет вопросы, варианты ответов, порядок и шкалы в рамках транзакции.
- `save_complex_test(header, content, assessment)` - сохраняет комплексную методику с заголовком, содержанием и параметрами оценки.
- `parse_pdf_methodology(file_path)` - извлекает текст и таблицы из PDF через `pdfplumber`, распознает вопросы и шкалы регулярными выражениями и возвращает подготовленную структуру для импорта.

Проведение тестирования:

- `create_test_session(s_id, t_id)` - создает сессию прохождения теста и возвращает ее UUID.
- `get_full_test_questions(t_id)` - получает активные вопросы выбранной методики вместе с порядком и JSON-вариантами ответов.
- `save_answer(sess_id, q_num, point_val)` - записывает ответ и начисленные баллы.
- `finalize_test_and_calculate(session_id, test_id)` - завершает сессию, суммирует баллы, рассчитывает уровни/шкалы риска и сохраняет результат.

Вспомогательные методы и отчеты:

- `decode_name(data)` - расшифровывает байтовое значение имени или безопасно преобразует его к строке.
- `log_report_generation(session_id, file_path, generated_by, binary_data)` - записывает факт формирования отчета.
- `archive_report_to_db(session_id, file_path, file_bytes, user_id)` - сохраняет бинарный файл отчета в БД.
- `get_test_results()` - получает сводный список результатов для административного раздела.
- `get_detailed_report_data(session_id)` - собирает данные ученика, теста, результата и ответов для отчета.
- `get_student_results(stud_uuid)` - получает историю результатов конкретного ученика.
- `get_available_tests()` - получает активные тесты, доступные ученику.

Пользователи и уведомления:

- `get_all_users()` - получает пользователей для административной таблицы.
- `get_user_notifications(user_id, only_unread=False)` - возвращает уведомления пользователя, опционально только непрочитанные.
- `create_notification(user_id, title, message, n_type='info')` - создает уведомление.
- `mark_notification_read(n_id)` - помечает уведомление прочитанным.
- `delete_notification(n_id)` - удаляет уведомление.

Все SQL-операции должны выполняться через контекстные менеджеры сервиса, чтобы соединения возвращались в пул, а незавершенные транзакции откатывались.

### `src/services/report_service.py`

Сервис формирования DOCX-отчетов и графического профиля результатов.

#### Класс `ReportService`

Все методы являются статическими и не требуют создания экземпляра.

- `generate_docx_report(data, output_path)` - создает документ Word с заголовком, сведениями об ученике, баллом, категорией риска, текстовым заключением, графиком и таблицей ответов. Очищает HTML-теги из заключения и сохраняет документ по указанному пути.
- `safe_decode(field)` - локальная функция внутри генератора отчета. Обрабатывает `memoryview`, `bytes`, `None` и обычные строки при выводе ФИО.
- `create_chart(data)` - строит графический профиль показателей через matplotlib и возвращает `io.BytesIO` с изображением для вставки в DOCX.

### `src/services/encryption_service.py`

Файл существует, но не содержит реализованного кода. Вспомогательное шифрование имен фактически вызывается из `DatabaseService`/`src/utils/encryption.py` или SQL-логики текущей реализации.

### `src/services/test_service.py`

Файл присутствует в структуре проекта, но рабочих классов и функций в текущем содержимом не обнаружено. Бизнес-логика тестов находится в `DatabaseService` и `TestTakingView`.

## 6. Модели предметной области

### `src/models/__init__.py`

Реэкспортирует `User`, `Student`, `Class`, `School`, `PsychologicalTest` и `TestResult`.

### `src/models/user.py`

#### `User`

Dataclass пользователя: `id`, `login`, `email`, `role`, `school_id`, `is_active`, `is_verified`, `created_at`.

- `from_db(row)` - создает `User` из кортежа колонок PostgreSQL.

### `src/models/student.py`

#### `Student`

Dataclass ученика. ФИО представлены полями `first_name_enc`, `last_name_enc`, `middle_name_enc`, то есть предполагается зашифрованное/байтовое хранение.

### `src/models/class_model.py`

#### `Class`

Dataclass школьного класса: школа, учебный год, название, параллель, буква, классный руководитель и статус.

- `from_db(row)` - создает объект из строки БД.

### `src/models/school.py`

#### `School`

Dataclass школы: название, адрес, телефон, электронная почта, статус и дата создания.

- `from_db(row)` - создает объект из строки БД.

### `src/models/test_model.py`

#### `PsychologicalTest`

Dataclass психологической методики: код, название, описание, версия, число вопросов, статус и дата создания.

- `from_db(row)` - создает объект из строки БД с безопасными значениями версии, количества вопросов и статуса при отсутствии длинных колонок.

### `src/models/result.py`

#### `TestResult`

Dataclass результата: идентификатор, сессия, уровень риска, числовой балл, заключение, флаг обработки и дата.

- `from_db(row)` - создает объект результата из строки БД.

## 7. GUI: общие окна

### `src/gui/__init__.py`

Маркер пакета GUI. Собственной логики нет.

### `src/gui/styles/__init__.py`

Содержит глобальную строку `STYLESHEET` с QSS-правилами для виджетов: фон, шрифты, заголовки, кнопки, поля ввода, таблицы, статусные сообщения и вкладки.

### `src/gui/auth_window.py`

#### `AuthWindow(QDialog)`

Модальное окно входа.

- `__init__(auth_service, parent=None)` - сохраняет сервис, настраивает заголовок, стиль и интерфейс.
- `setup_ui()` - создает поля логина/пароля, кнопку входа, переключатель видимости пароля, кнопку регистрации и статусную надпись.
- `toggle_password_visibility()` - переключает `QLineEdit` между режимами `Password` и обычным текстом.
- `show_register_window()` - открывает `RegisterWindow`, а после успешной регистрации возвращает пользователя к форме входа.
- `login()` - вызывает `AuthService.authenticate_user`, отображает ошибку при отказе и принимает диалог при успехе.
- `get_user_data()` - возвращает словарь данных успешно авторизованного пользователя.

Сигнал `login_successful` предназначен для передачи словаря пользователя, хотя основной сценарий приложения использует результат `exec()` и `get_user_data()`.

### `src/gui/register_window.py`

#### `RegisterWindow(QDialog)`

Окно создания учетной записи.

- `__init__(auth_service, parent=None)` - сохраняет сервисы, задает размер и строит форму.
- `setup_ui()` - создает поля логина, email, пароля, подтверждения, выбора роли и кнопки регистрации/отмены.
- `_add_input_field(layout, label_text, placeholder, is_password=False)` - добавляет подпись и поле ввода, возвращает созданный `QLineEdit`.
- `_add_label(layout, text)` - добавляет стилизованную подпись поля.
- `validate_inputs(login, email, password, confirm)` - проверяет логин регулярным выражением, email, минимальную длину пароля и совпадение подтверждения; возвращает текст ошибки или `None`.
- `handle_registration()` - валидирует форму, проверяет уникальность логина, хеширует пароль, вставляет пользователя в БД и закрывает диалог при успехе.

### `src/gui/main_window.py`

#### `MainWindow(QMainWindow)`

Корневое окно после авторизации.

- `__init__(auth_service, db_service, user_data=None, parent=None)` - сохраняет сервисы и пользователя, создает интерфейс и либо загружает кабинет, либо открывает авторизацию.
- `setup_ui()` - создает `QStackedWidget`, меню и статусную строку.
- `create_menu_bar()` - добавляет меню смены пользователя, выхода и справки с горячими клавишами `Ctrl+L` и `Ctrl+Q`.
- `on_login_success(user_data)` - очищает стек и создает кабинет по роли: `AdminDashboard` для `admin`/`psychologist`, `StudentDashboard` для `student`.
- `show_auth_window()` - запускает авторизацию, когда `MainWindow` используется напрямую или после выхода.
- `logout()` - подтверждает смену пользователя, сбрасывает текущего пользователя и показывает окно входа.
- `show_about()` - показывает сведения о программе, версии и школе.

## 19. Важные особенности текущего состояния

1. Основной рабочий интерфейс - desktop GUI; API-папка пока является каркасом.
2. Для роли `psychologist` `MainWindow` сейчас создает `AdminDashboard`, несмотря на наличие отдельного `PsychologistDashboard`.
3. Часть файлов создана для будущего разделения ответственности, но пока пустая.
4. Подключение к БД происходит при создании `DatabaseService`, поэтому запуск без PostgreSQL и корректного `.env` может завершиться ошибкой.
5. GUI-тесты пропускаются автоматически из-за требования дисплея.
6. Пароли хранятся в виде bcrypt-хешей; это не то же самое, что обратимое шифрование персональных данных.
7. Для ФИО используются байтовые/зашифрованные значения, поэтому GUI и отчетный сервис содержат безопасное декодирование.
